Source snapshot and regeneration

The original seven views cite 4b0b2d8; the seven deeper views cite 0e64128f. Those snapshots have identical runtime source. Every node's evidence is checked against its declared commit. The main overview remains byte-for-byte identical to the original.

The rule example uses synthetic records and relative times. Sequence spacing represents call order, not measured latency. Exploit catalogue associations and NVD links are separate from activity observed in traffic.

Open index.html locally, or open any standalone diagram HTML directly. Generated diagrams embed their viewer assets, source excerpts and software notices. The editable specifications are under specs/; automated receipts and content hashes are summarized in verification.json. The separate visual review record identifies the artifact bytes inspected in light and dark mode.

With Archify installed globally, run these commands from the repository root. Set ARCHIFY_CLI to a custom bin/archify.mjs path when needed. Rendering uses Node.js 18+ and Archify's browser-check runtime.

node docs/diagrams/render.mjs
node docs/diagrams/render.mjs --check

The render command verifies sources against the pinned revision and runs validation, delivery, artifact checks and browser checks. Pass a diagram name, such as distributed, to rebuild just that view. It publishes verification.json only when every diagram has a current passing receipt. --check checks specification and HTML hashes against that record; it does not rerun browser checks. The published receipts distinguish automated verification from visual review.
